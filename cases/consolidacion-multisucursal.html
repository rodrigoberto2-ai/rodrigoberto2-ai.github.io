Consolidación Multi-Sucursal con Power Query

Ejemplo con datos sintéticos — combinar archivos de ventas de distintas sucursales, cada uno con formato ligeramente distinto, en una tabla única y limpia lista para el modelo.

El problema

  • 12 archivos mensuales por sucursal, nombres de columna inconsistentes
  • Nombres de sucursal escritos de formas distintas ("MADRID", "Madrid ", "madrid-centro")
  • Fechas en 3 formatos distintos según el archivo de origen
  • Columnas de meses en formato ancho (una columna por mes) en vez de filas

El resultado

  • Una consulta que se actualiza sola al añadir un archivo nuevo a la carpeta
  • Nombres de sucursal estandarizados con una tabla de referencia
  • Una columna de fecha, un tipo de dato, sin ambigüedad
  • Formato largo (una fila por sucursal/mes) — listo para relacionar con el modelo
Editor de Power Query — fx = Tabla.TransformColumnTypes(#"Filas filtradas", {{"Fecha", type date}})

Fragmento del código M generado (editable a mano cuando el editor visual no alcanza).

CÓDIGO M — NORMALIZACIÓN DE SUCURSAL

// Estandariza variantes de escritura antes de combinar con Dim_Sucursal let Origen = Table.TransformColumns(#"Encabezados promovidos", {{"Sucursal", each Text.Trim(Text.Upper(_)), type text}}), Reemplazado = Table.ReplaceValue(Origen, "MADRID-CENTRO", "MADRID", Replacer.ReplaceText, {"Sucursal"}) in Reemplazado

ENFOQUE

Consulta parametrizada a nivel de carpeta (no archivo por archivo), para que un mes nuevo solo signifique añadir un CSV, no editar la consulta. La limpieza de nombres va antes del merge con la dimensión, no después — así el merge no falla silenciosamente por una variante no reconocida. Los datos son sintéticos, generados para este caso — no proceden de ningún cliente real.
