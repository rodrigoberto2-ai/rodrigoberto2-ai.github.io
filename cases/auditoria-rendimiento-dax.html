Dónde se iba el tiempo

Motor de fórmulas (DAX) vs. motor de almacenamiento (VertiPaq), por consulta — visto en el analizador de rendimiento de Power BI.

Motor de fórmulas (DAX) — el 94% del tiempo total estaba aquí, concentrado en una sola medida Motor de almacenamiento
Antes — 7.9sRanking de Clientes
// Recalcula el ranking completo por cada fila visible en la tabla Ranking Cliente = COUNTROWS( FILTER( ALL( Clientes ), CALCULATE( [Ventas Totales] ) > [Ventas Totales] ) ) + 1

FILTER sobre ALL(Clientes) fuerza un escaneo fila-por-fila de toda la tabla de clientes, dentro del motor de fórmulas, para cada celda visual. Con 40k clientes y 60 filas visibles, son ~2.4M evaluaciones de contexto.

Después — 0.4sRanking de Clientes
// RANKX está optimizado por el motor para este patrón exacto Ranking Cliente = RANKX( ALLSELECTED( Clientes ), [Ventas Totales], , DESC, Dense )

RANKX delega gran parte del trabajo al motor de almacenamiento (VertiPaq) en vez de iterar fila por fila en el motor de fórmulas. ALLSELECTED en vez de ALL respeta los filtros de página/informe pero ignora el filtro de la propia visual — el ranking no colapsa a "1" cuando se filtra una sola fila.

ENFOQUE

El primer paso no fue tocar el DAX — fue medir con el analizador de rendimiento para ver cuánto tiempo se iba al motor de fórmulas frente al motor de almacenamiento, y en qué visual exactamente. Una sola medida (el ranking) explicaba el 94% del tiempo total; optimizar las otras tres apenas cambiaba la experiencia del usuario. La regla general aplicada: cuando una medida itera fila por fila sobre una tabla completa (FILTER + ALL), buscar la función nativa equivalente (RANKX, TOPN) que el motor de almacenamiento puede resolver de forma más directa. Los datos y tiempos son sintéticos, construidos para ilustrar el proceso — no proceden de ningún cliente real.
