DAX · Performance Analyzer

Auditoría de rendimiento de un modelo DAX

Un informe tardaba más de 8 segundos en cargar. Lo medí con el Performance Analyzer y reescribí la medida que lo frenaba hasta bajar de 1 segundo. Datos sintéticos.

Tiempo de consulta (antes)8.4 s
Tiempo de consulta (después)0.7 s▾ 92%
Medidas reescritas3
Filas del modelo2.1 M

Dónde se iba el tiempo

Tiempo por consulta en el Performance Analyzer: motor de fórmulas frente a motor de almacenamiento.

Motor de fórmulas (DAX): aquí estaba el 94 % del tiempo, casi todo en una sola medida Motor de almacenamiento
Antes, 7.9sRanking de Clientes
// Recalcula el ranking completo por cada fila visible en la tabla Ranking Cliente = COUNTROWS( FILTER( ALL( Clientes ), CALCULATE( [Ventas Totales] ) > [Ventas Totales] ) ) + 1

FILTER sobre ALL(Clientes) recorre toda la tabla de clientes en el motor de fórmulas, una vez por cada celda. Con 40.000 clientes y 60 filas en pantalla son unos 2,4 millones de evaluaciones.

Después, 0.4sRanking de Clientes
// RANKX está optimizado por el motor para este patrón exacto Ranking Cliente = RANKX( ALLSELECTED( Clientes ), [Ventas Totales], , DESC, Dense )

RANKX deja casi todo el trabajo al motor de almacenamiento. Con ALLSELECTED en vez de ALL, el ranking respeta los filtros de la página pero no el de la propia tabla, así que no se queda en «1» al filtrar una fila.

ENFOQUE

No empecé por el DAX sino midiendo. Una sola medida, el ranking, se llevaba el 94 % del tiempo; optimizar las otras tres casi no se notaba. Cuando una medida recorre una tabla entera con FILTER + ALL, busco la función que el motor de almacenamiento resuelve directamente, como RANKX o TOPN.
